# Changelog

Формат — [Keep a Changelog](https://keepachangelog.com/ru/1.1.0/), версия — семантическая.
Версия намеренно продолжает нумерацию приложения в форке `DnsFakeIpServer` (`4.2.6`), чтобы DNS Server считал
сборки из этого репозитория более новыми, чем уже установленные.

## [Unreleased]

### Added

- Тестовый проект `tests/FakeIpDnsApp.Tests` (xunit 2.9.2, `net10.0`) в `FakeIpDnsApp.sln`: 173 теста на
  `BaseIpAllocator` (обход кольца, переполнение счётчика, `TryReturn`, фабрики, 16 потоков), `IpLease` и
  `IPAddressRange`. Проверяемые модули не ссылаются на хостовые DLL, поэтому тесты собираются и запускаются без
  `libs\`. `App.cs`, `Services/` и `Protos/` не покрыты: им нужны `IDnsServer`, `nft` или gRPC-агент.

### Changed

- Максимальный размер диапазона зафиксирован: `BaseIpAllocator.MaxRangeSize` = `int.MaxValue` адресов (было
  `uint.MaxValue`). Крупнейший CIDR — `/2` для IPv4 и `/98` для IPv6: `/1` и `/97` — это `2^31` адресов, на один
  больше лимита; вместе с ними отвергаются `0.0.0.0/0` и `::/0`. Теперь количество адресов аренды всегда
  помещается в `int`.
- `dnsApp.config` больше не содержит глобально маршрутизируемый префикс: `ipV6Range` по умолчанию — `fc00::/110`
  (ULA, RFC 4193) вместо `/110` из чужого `/48`, выделенного хостинг-провайдеру. Рабочий IPv6-диапазон обязан быть
  собственным и глобально маршрутизируемым — в README для этого отдельный раздел с объяснением про приоритет ULA
  и про то, что Windows-клиент при двух стеках уйдёт на IPv4.

### Fixed

- Сниппет `versions.json` в README приведён к фактическому пину (`v15.6.2`), примеры `get-libs.ps1` больше не
  ссылаются на релизы, которых нет в примере, а комментарий `Directory.Build.props` не утверждает, что контракт
  хоста — `10.0`.
- `AGENTS.md` и `README.md`: лимит размера диапазона — `int.MaxValue` адресов, крупнейший CIDR `/2` для IPv4 и
  `/98` для IPv6; раздел про тесты и карта репозитория с `tests/FakeIpDnsApp.Tests`.
- `BaseIpAllocator.Allocate` больше не прижимает аренду к концу диапазона (`start = RangeSize - count`): если до
  конца диапазона осталось меньше адресов, чем просят, арендуется остаток хвоста. Прежнее поведение повторно
  выдавало адреса активной предыдущей аренды: на `192.0.2.0/29` и трёх адресах на домен `192.0.2.5` выдавался
  дважды за виток, на `10.0.0.0-10.0.0.9` и четырёх адресах — `10.0.0.6` и `10.0.0.7`.
- Последовательность выдачи снова равна обходу кольца без пропусков и повторов; при разных
  `maxIpv4AddressesPerDomain` / `maxIpv6AddressesPerDomain` у одного диапазона выдача остаётся ровной — разброс
  количества выдач между адресами диапазона не больше 1.
- Текст ошибки размера диапазона: вместо `Ip range is too big. For ipv6 supported cidr >= 96` — сообщение с
  фактическим количеством адресов, лимитом и требуемыми префиксами. Прежний текст противоречил проверке:
  `/96` — это ровно `2^32` адресов, и он тоже не поддерживается.
- `IPAddressRange.ParseRange` читает байты адресов беззнаково (`isUnsigned: true`): диапазоны, пересекающие
  старший бит адреса, больше не отвергаются как «перевёрнутые» — работают `100.0.0.1-200.0.0.1`,
  `0.0.0.1-255.255.255.255`, `::1-ffff::1` и `2001:db8::-ffff:ffff:ffff:ffff:ffff:ffff:ffff:ffff`.
- `IPAddressRange.ParseCidr` проверяет отрицательную длину префикса: `10.0.0.1/-1` даёт `FormatException` вместо
  `IndexOutOfRangeException` в маскировании байтов.
- `IPAddressRange.ParseRange` проверяет результат `TryWriteBytes` вместо `out _` и не строит адрес из
  недозаписанных байтов.
- `LocalNftIpMap.CreateMappingsAsync`: смешанный по семействам набор больше не роняет приложение —
  `Distinct().IsSingle()` при двух семействах бросает `InvalidOperationException`, из-за чего ветка разделения на
  IPv4- и IPv6-команды была недостижимой.
- `LocalNftIpMap`: stderr процесса `nft` вычитывается параллельно ожиданию завершения — переполненный буфер pipe
  больше не вешает запрос навсегда; у процесса удаления убран `RedirectStandardOutput`, который никто не читал.
  `ExitCode` удаления по-прежнему не проверяется: удалить несуществующий элемент — штатная ситуация.
- `IpLease`: `IReadOnlyCollection<IPAddress>.Count` больше не может стать отрицательным — аллокатор не принимает
  диапазон крупнее `int.MaxValue` адресов, поэтому приведение `Count` к `int` безопасно.
- `App.PostProcessAsync`: если в ответе нет ни одной A- или AAAA-записи (например, только CNAME), возвращается
  исходный ответ — раньше клиент получал `NOERROR` с пустым ANSWER.

## [4.2.8] - 2026-11-25

### Changed

- Зависимости хоста подняты до Technitium DNS Server 15.6.2: `dnsServerTag` = `v15.6.2`,
  `technitiumLibraryTag` = `dns-server-v15.6.2`. Собранные ссылки: `DnsServerCore.ApplicationCommon` 10.2,
  `TechnitiumLibrary` 7.2, `TechnitiumLibrary.Net` 15.2.1.
- Код приложения под новую версию не менялся: интерфейсы `IDnsApplication` и `IDnsPostProcessor` между 15.2.0 и
  15.6.2 идентичны, новые члены появились только у `IDnsServer` (`DirectQueryAsync` с `IPEndPoint`,
  `IsLocallyServedZone`, `WriteLog(message, ex)`), а её приложение только использует. Предупреждения `CS8625` на
  передачу `null` в `GetPropertyValue` исчезли, осталось одно `CS8602` в `App.cs`.

## [4.2.7] - 2026-11-25

### Added

- Отдельный репозиторий с собственной git-историей: 17 коммитов приложения импортированы из `Apps/FakeIpRouting`
  форка Technitium DNS Server (авторы, даты и сообщения сохранены).
- `build/get-libs.ps1` — скачивание и сборка compile-time сборок хоста (`DnsServerCore.ApplicationCommon`,
  `TechnitiumLibrary`, `TechnitiumLibrary.Net`) по тегам из `versions.json`; результат в `libs/`.
- `build/package.ps1` — `dotnet publish` + плоский архив `dist/FakeIpDnsApp-<version>.zip` для установки в
  `Settings → Apps`; сборки хоста и `.pdb` в архив не попадают.
- `Directory.Build.props` (`net10.0`, C# 14, `Nullable`, плоский путь вывода), `versions.json`, `FakeIpDnsApp.sln`,
  `README.md`, `LICENSE` (GPL-3.0-only), этот файл.

### Changed

- Проект переименован в `FakeIpDnsApp`: пространства имён `FakeIpRouting*` → `FakeIpDnsApp*`, сборка
  `FakeIpDnsApp.dll`, класс приложения `App` (как у официальных DNS App), корневое пространство имён в `.csproj`.
- Ссылки на хостовые сборки вместо `ProjectReference`: `<Reference>` + `HintPath` в `libs/` и `Private=false`.
  Решение больше не нужно, исходники Technitium не тянутся.
- `Grpc.Tools` `2.82.0-pre1` → `2.80.0` (стабильная версия, та же линия, что у `Grpc.Net.Client 2.80.0`).
- Поддержка только `net10.0`: старые целевые платформы DNS Server не обслуживаются.
- Пиннинг зависимостей в `versions.json` — полные имена тегов upstream-репозиториев: `dnsServerTag` = `v15.2.0`,
  `technitiumLibraryTag` = `dns-server-v15.2.0` (префикс `dns-server-` теперь часть имени тега, а не отдельное поле:
  у TechnitiumLibrary своей нумерации нет, его теги названы по релизу DNS Server). Добавлены `-ReleaseVersion`
  (сдвигает номер версии внутри обоих тегов), `-DnsServerTag`, `-LibraryTag` и `-DryRun`, проверка имени тега по
  маске и проверка существования тега в репозитории до начала клонирования.

### Fixed

- `get-libs.ps1` на уже клонированном репозитории не переключал версию: существующая копия в `.deps/` теперь
  добирает нужный тег и переключается на него, причём по явному `refs/tags/<тег>` — имя тега двусмысленно с
  локальной веткой, которую создаёт `git clone --branch <тег>`.
- Корневой параметр `disabled` в `dnsApp.config` не применялся: код читал ключ `disable` и всегда получал `false`.
  Теперь читается `disabled`, приложение действительно можно выключить конфигурацией.

### Removed

- Пустой `README.md` внутри папки приложения (описание переехало в корень репозитория).

## [4.2.6] и раньше

Разработка в папке `Apps/FakeIpRouting` форка Technitium DNS Server: диапазоны CIDR и диапазоны-диапазоны,
несколько диапазонов с собственными лимитами адресов на домен, gRPC-агент маппинга, `nft`-таблицы и maps,
аллокация адресов с освобождением по TTL, `ignoreCase`, `maxTtl`, отключение кэширования ответа.
Полная история — в `git log` (коммиты сохранены при импорте).
